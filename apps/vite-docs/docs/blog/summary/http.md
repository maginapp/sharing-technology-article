### 常见的http状态码

#### 1xx信息类


* 100 Continue：表明客户端的请求的初始部分已被服务器接收且正确，客户端应继续发送请求的其余部分。
* 101 Switching Protocols：服务器根据客户端的请求，正在切换协议，如从 HTTP 协议切换到 WebSocket 协议。
* 103 Early Hints：服务器在正式响应前，提前向客户端发送一些提示信息，让客户端可以提前开始一些准备工作，例如预加载相关资源等。

#### 2xx成功类


* 200 OK：表示请求已成功，请求所期望的响应头或数据体将随此响应返回。
* 201 Created：用于表示请求已成功，且服务器创建了一个新的资源。
* 204 No Content：服务器成功处理了请求，但不需要返回任何实体内容，通常用于只需要更新资源状态，而不需要返回数据的情况。
* 206 Partial Content：服务器成功处理了部分范围的 GET 请求，客户端可以通过此状态码获取部分资源内容，比如在下载大文件时支持断点续传功能就会用到这个状态码。

#### 3xx重定向类


* 301 Moved Permanently：表示请求的资源已被永久移动到新的 URL，今后应使用新的 URL 访问该资源。
* 302 Found：请求的资源临时存在于另一个 URL，客户端应使用新的 URL 再次发送请求，但后续访问仍可使用原 URL。
* 304 Not Modified：如果客户端发送了附带条件的请求，而服务器发现资源未被修改，会返回此状态码，让客户端使用本地缓存的资源。
* 307 Temporary Redirect：与 302 类似，也是临时重定向，但要求客户端在重定向时保持原请求方法不变，常用于 POST 请求重定向等场景。
* 308 Permanent Redirect：类似于 301 永久重定向，不同的是 308 要求客户端在重定向时保持原请求方法和请求内容不变。

#### 4xx客户端错误类

* 400 Bad Request：表示客户端发送的请求有语法错误或无法被服务器理解。
* 401 Unauthorized：客户端请求需要用户认证，若未提供有效的身份验证信息或验证失败，会返回此状态码。
* 403 Forbidden：服务器理解请求，但拒绝执行，通常是因为客户端没有足够的权限访问资源。
* 404 Not Found：服务器无法找到请求的资源，可能是 URL 输入错误或资源已被删除等原因。
* 405 Method Not Allowed：服务器知道客户端请求的方法，但目标资源不支持该方法，比如在只允许 GET 请求的资源上使用了 POST 方法。
* 406 Not Acceptable：服务器根据客户端发送的 Accept 请求头，发现无法提供符合客户端要求的响应内容，例如客户端请求 JSON 格式数据，而服务器只能提供 XML 格式数据。
* 413 Payload Too Large：客户端发送的请求实体数据过大，超出了服务器能够处理的范围，服务器拒绝处理该请求。
* 429 Too Many Requests：客户端发送请求的频率超过了服务器的限制，用于防止客户端对服务器进行恶意攻击或过度请求。

#### 5xx服务端错误类

* 500 Internal Server Error：服务器内部出现了错误，无法完成请求。
* 501 Not Implemented（未实现），服务器不支持完成客户端请求所需的功能或方法，无法处理该请求。比如客户端发起了一个服务器不支持的特定 HTTP 方法（如扩展的自定义方法）的请求，或者请求的功能是服务器尚未实现的新特性，服务器就会返回 501 状态码。
    * 新 HTTP 方法请求：当客户端使用了新的、尚未被服务器支持的 HTTP 方法发送请求时，如使用了某个新提出但服务器还未适配的方法，服务器会返回 501 状态码。
    * 特定功能未实现：客户端请求服务器执行一些特殊功能，如对某种特定数据格式的处理或特殊的认证方式，而服务器没有实现这些功能，也会返回此状态码。
* 502 Bad Gateway：作为网关或代理的服务器，从上游服务器收到了无效的响应。
* 503 Service Unavailable：服务器暂时无法处理请求，通常是由于服务器过载或正在维护等原因。
* 504 Gateway Timeout：服务器作为网关或代理，在等待上游服务器响应时超时，通常是由于上游服务器无响应或响应过慢。
